## 2026-05-27 — task-006: Implement GET /render/stream.mjpeg MJPEG stream endpoint

- For long-lived streaming responses, do NOT call `disconnectFromHost()`/`deleteLater()` at the end of the route handler — just return, leaving the socket open.
- Parent the `QTimer` to the socket (`new QTimer(socket)`) so it is automatically destroyed if the socket is deleted by any path, preventing dangling timer callbacks.
- Use `socket` (not `this`/HttpServer) as the context object in `QTimer::timeout` lambda connections — the connection is then auto-disconnected when the socket is destroyed, eliminating any use-after-free risk.
- Capture `m_browser` as a local `AnoaBrowser *browser` before the lambda to avoid capturing `this` in a lambda whose lifetime may exceed the HttpServer's. Raw pointer capture is safe here because AnoaBrowser outlives all sockets.
- The `disconnected` signal handler must call `frameTimer->stop()` BEFORE `socket->deleteLater()` — stopping first prevents a queued timeout firing on a socket in the process of deletion.
- `QPixmap::save(QIODevice*, "JPEG", quality)` takes quality 0–100; passing 70 as the third argument produces JPEG quality 70 without needing a separate encoder setup.
- The 512 KB back-pressure check (`socket->bytesToWrite() > 512*1024`) should run before any capture work — fail fast before calling `grab()`.

## 2026-05-27 — task-003: Implement GET /render/html endpoint

## 2026-07-29 — task-002: anoa-term terminal viewer client

- anoa-term is intentionally Qt-free (POSIX sockets + termios only) — the server-side PPM endpoint means the client needs no image decoder, keeping it a single ~450-line file.

- Non-interactive testing recipe: `(sleep 2; printf '\033[<0;40;12M...q') | script -q out.txt ./anoa-term ...` gives the client a real pty; under `script` the winsize falls back to 80×24, which makes click-coordinate assertions deterministic.
- Click mapping: pageX = cellX * viewportW / imgW using the ACTUAL PPM dimensions from the response (KeepAspectRatio means returned size ≠ requested size).

## 2026-07-29 — task-004: anoa-term high-resolution gfx mode (iTerm2/kitty)

- Halfblock pixelation is inherent (1 cell = 1×2 px); the fix is terminal image protocols: OSC 1337 (iTerm2/WezTerm) and kitty APC G (kitty/ghostty), auto-detected from TERM/TERM_PROGRAM/KITTY_WINDOW_ID.
- kitty protocol: re-transmitting with the same image id (i=1) AND placement id (p=1) replaces the previous frame atomically — no a=d delete needed, no flicker. Payload must be chunked ≤4096 base64 bytes; only the first chunk carries control keys; C=1 keeps the cursor in place.
- iTerm2 protocol: compute the aspect-correct cell rect yourself and send preserveAspectRatio=0 — letting the terminal letterbox (preserveAspectRatio=1) breaks click-coordinate mapping.
- Cell pixel aspect via XTWINOPS: send \033[16t right after entering raw mode (before any other input), read \033[6;<h>;<w>t with a select() timeout; fall back to 8×16. Under `script` ptys nothing responds — the fallback keeps tests deterministic.
- Skip re-sending the image when the PNG body is byte-identical to the previous frame — static pages then cost zero terminal bandwidth and never flicker.
- PNG dimensions come straight from the IHDR chunk (bytes 16-23, big-endian) — no decoder needed for layout math.
- Unified click mapping through a DisplayMap {dispCols, dispRows, viewportW/H} works for both backends: halfblock dispCols=ppmW, dispRows=ceil(ppmH/2); gfx = computed cell rect.

## 2026-07-30 — task-014: macOS cask quarantine fix (ad-hoc app on Apple Silicon / macOS 26)

- brew's `--no-quarantine` CLI flag was REMOVED in Homebrew 6 — documenting it is a hard error for users. Handle quarantine inside the cask instead.
- Ad-hoc-signed (non-notarized) app: if launched even ONCE while com.apple.quarantine is set, Gatekeeper caches a reject by cdhash and the kernel SIGKILLs it thereafter (exit 137) even after the flag is removed; macOS 26 also deletes the bundle. The flag must be cleared BEFORE first launch.
- Cask `postflight` must target `appdir.join("anoa-browser.app")`, NOT `staged_path` — by postflight time the .app has already been moved out of the Caskroom staging dir (staged_path find matches nothing → 292 files stayed quarantined).

- Local verdict cache is polluted by prior unquarantined runs of the same cdhash — "it runs on my machine" is NOT proof the postflight worked; verify by counting remaining quarantine xattrs (must be 0), not by launching.
- The shipped ad-hoc signature is NOT strict-valid (codesign -v --strict: "QtWebEngineCore.framework embedded framework contains modified or invalid version") — a known Qt+codesign issue — but that only matters under quarantine/Gatekeeper strict eval. Unquarantined, the app runs fine (proven: --version, headless, /json/version). Strict-valid signing is deferred (needs proper inside-out Versions/A signing or notarization).

## Embedded terminal, navigation shortcuts, window chrome (2026-08-01)

- `anoa-browser terminal` with no target now hosts its own browser in-process.
  The decision is made by the argv pre-scan in main.cpp, not from Config: the
  defaults of termHost/termPort are indistinguishable from a user typing them,
  and `--term-port 9222` must keep meaning "connect to the browser already
  there". Only this one case builds QApplication; --term-port and --cdp stay
  QCoreApplication clients so they still work over SSH with no browser present.

- The GUI chrome is a *wrapper* around AnoaBrowser, never a child of it.
  http_server.cpp captures with `m_browser->grab()` and reports
  `m_browser->width()/height()` as the viewport that /render/click coordinates
  are measured in. A toolbar inside the view would appear in every screenshot
  and shift every click by its own height. Verified after the change: row 0 of
  a headed capture is a single colour and the viewport still reads 1280x720.

- Alt-arrow parsing matches its prefix byte by byte against what has arrived,
  rather than waiting for six bytes. "Wait for six" stalls the input buffer on
  every other CSI beginning with '1' — Home is ESC [ 1 ~, four bytes — until the
  user happens to press something else. Pinned by TERM-NAV-03.

- Esc is deliberately not the URL prompt's cancel key. Distinguishing a lone Esc
  from the start of an arrow or mouse report needs a timeout, and guessing is
  exactly what caused bug-002. Ctrl-C/Ctrl-G cancel instead; Esc-led sequences
  are swallowed whole with the same partial-buffering discipline as the main
  path.

- macOS cannot validate the pty suites. terminal_http.test.js and
  terminal_cdp.test.js skip themselves because they call GNU `script -q -c` and
  macOS ships BSD `script`; port_layout.test.sh fails several cases on
  "extra_args[@]: unbound variable", which is bash 3.2 under nounset (macOS's
  /bin/bash) and not a behaviour difference. Do not read either as a regression
  on a Mac — check them on Linux/CI. build_shape, extensions, the unit suites
  and vitest all run fine here.

- bug-004 filed: /render/screenshot.ppm truncates responses over ~1 MB while
  Content-Length declares the full size. Pre-existing and unrelated to this
  work; invisible to every in-repo caller because they all request scaled
  frames.

## Agent CLI, the `anoa` rename, and a release that deleted itself (2026-08-01)

  and wait for it to pass. It builds and smoke-tests every package and publishes
  nothing. This is written up in AGENTS.md (Known Gotchas) and docs/BUILDING.md

- The reason: v0.4.1 shipped a macOS app that deleted itself on first run. An

  invalid, so Gatekeeper SIGKILLed the process and removed the app. Every check
  in CI passed — `spctl --assess` said "accepted, source=Notarized Developer ID"
  — because the stray directory reappeared *after* the guard and before `tar`.
  Verify the artifact, not the working tree.

- Diagnosing it: extract the published tarball and run
  `codesign --verify --deep --strict` on the .app. That is what said "embedded
  framework contains modified or invalid version" and named the framework.
  `spctl` alone passed on the broken bundle and told us nothing.

- The agent commands (`anoa open|snapshot|click|fill|…`) attach to a browser
  that is already running. State that has to survive between commands lives in
  the *page*: `snapshot` writes data-anoa-ref onto the DOM nodes, which is why a
  ref minted by one process resolves in the next. Do not try to cache refs in a
  file or a daemon — the DOM already has exactly the right lifetime.

- Clicks go through Input.dispatchMouseEvent at a hit-tested point, never
  el.click(). The synthetic click skips hit testing and would "click" through a
  consent banner, which is the failure that makes an agent believe it dismissed
  something it did not.

- `fill` sets the value through the prototype setter before dispatching
  input/change. React tracks the last value it wrote on the node and ignores an
  event whose value it believes is unchanged; assigning el.value directly is
  silently a no-op there.

- macOS testing gaps closed: tests/e2e/terminal_e2e.py drives the viewer through
  pty.fork() instead of GNU `script -q -c`, so it runs on macOS where
  terminal_http/terminal_cdp skip themselves. helpers.js now probes for
  build/anoa.app/Contents/MacOS/anoa, which removes the hand-made build/anoa
  symlink that only survived until the next clean build.

- Homebrew renames need cask_renames.json / formula_renames.json at the tap
  root, mapping old -> new. Deleting the old cask/formula without them strands
  existing installs: `brew upgrade` reports "No available formula or cask" and
  they silently stop receiving updates.

- GLVND libraries (libGL, libGLX, libGLdispatch, libEGL, libOpenGL) must not sit
  in front of the host's. Their whole job is to locate the graphics driver
  installed on the running machine, so a vendored copy hunts for the build box's
  driver instead: "qglx_findConfig: Failed to finding matching FBConfig" then
  abort, on a desktop whose own GL is fine. They cannot just be dropped either --
  the binary links libOpenGL.so.0 directly and Debian's libgl1 does not provide
  it, so excluding them outright kills even --headless, which needs no GL at all.
  The bundle keeps them in lib/gl, outside the search path, and anoa.sh appends
  that directory only when the host has no libOpenGL.so.0.

- qputenv("QTWEBENGINE_CHROMIUM_FLAGS", ...) overwrites. AnoaBrowser discarded
  whatever the caller had exported, so the escape hatch in our own README
  (QTWEBENGINE_CHROMIUM_FLAGS=--disable-gpu) did nothing, and the Dockerfile's
  --disable-gpu was dropped on every run. Inherited flags are appended now, last,
  so a deliberate override wins. Verified by --single-process producing zero
  QtWebEngineProcess helpers.

- Do not trust an x86_64 container on Apple Silicon for graphics work. qemu
  breaks Mesa's software renderer ("LLVM ERROR: 64-bit code requested on a
  subtarget that doesn't support it", "qemu: uncaught target signal 6") and the
  published build fails there identically to a broken one, so the run proves
  nothing either way. The container job in container.yml runs on a real x86_64
  runner and is the trustworthy signal.

- libX11 and libstdc++ are host-first libraries, alongside GL and glibc. The
  host's Mesa is dlopen()ed into the process and built against the host's copy
  of both, so ours in front leaves it unable to offer a usable FBConfig. Found
  by bisecting the bundle one library at a time on a real Ubuntu 24.04 box with
  glxinfo counting configs: 320 without the bundle, 0 with either of those two,
  320 with every other library in it. glxinfo is a far cheaper probe than
  launching the browser, and it isolates the cause in one number.

- Host-first cannot be decided per directory. GL spans libgl1, libglx0,
  libopengl0, libegl1 and libglvnd0, all separately installable, so one sentinel
  file answers for the set and is wrong in both directions — on one machine,
  libGL.so.1 alone meant ours shadowed the host's (GLX died), and libOpenGL.so.0
  alone meant the host's was kept and the binary would not start for want of
  libEGL.so.1. anoa.sh asks ldconfig per library and symlinks in only the gaps.

- Testing on a real Linux box beats any amount of reasoning about one. Xvfb
  with +extension GLX reproduces a desktop GLX failure faithfully; llm.irawan.science
  did in minutes what an emulated container could not do at all.

- Watch out for pkill -f matching the ssh command line itself: `pkill -f "port
  9333"` over ssh kills the shell running it, and the command returns silently
  with no output. `pkill -x anoa` matches the process, not the sentence about it.

- tests/coverage.sh names its build targets twice: once in TARGETS (the gcov
  object paths it measures) and once in the `cmake --build --target` list. Adding
  a unit lib to only the first passes `make test` and then fails `make coverage`
  with "Not Run", because the test binary was never built into build-coverage.

- `make test` builds the main anoa target too, not just the unit libs. A commit
  that deliberately leaves the tree unlinkable (task-002 of multi-tab did)
  therefore cannot run the unit suite at all — grepping its output for "tests
  passed" silently finds nothing rather than failing loudly.

- /render/click takes its coordinates as QUERY PARAMETERS, not a JSON body.
  A POST with a JSON payload returns "invalid coordinates" as a 400, which is
  easy to misread as the click having missed its target.

- Target.getTargetInfo must pass through for ids the registry does not know.
  Chromium owns targets we never registered — the browser target itself, service
  workers, a popup from window.open — and answering "No target with given id"
  for those broke Playwright's connectOverCDP outright: it asks about the
  browser target during the handshake, and a client cannot attach to a browser
  that denies its own existence. Applies to any Target command that can name a
  non-tab target.

- Playwright's afterAll calls browser.close(), which on a connectOverCDP
  connection closes the real browser. Chaining the Playwright suite into another
  e2e suite that attaches to the same instance therefore fails the second one
  for reasons that have nothing to do with the code under test.

- The e2e suites assume a browser with ONE tab: they take contexts()[0].pages()[0]
  and reason about counts. Running them against an instance left holding tabs
  from an earlier probe silently changes which page they drive, and a case can
  drop out of the run entirely. Start a fresh browser per suite now that tabs
  exist.

- Google Chrome squats 127.0.0.1:9222 when its remote-debugging port is on (the
  claude-in-chrome extension does this). anoa binds *:9222 on IPv6, so a request
  to 127.0.0.1:9222 reaches CHROME instead, and every probe describes the wrong
  browser: four targets including browser_ui, no anoaTabId, and /json/list
  looking as if the tab registry had broken. Check `lsof -nP -iTCP:9222` before
  believing a discovery result, or verify on a port nothing else holds.

- `pkill -f anoa` matches the path of anything with "anoa" in its command line,
  including editors and this repo's own tooling. `pkill -x anoa` matches the
  process name only.

- QStackedLayout lays out only the widget it is showing. A background tab keeps
  the size it was born with (100x30), so /render/screenshot.png?tab=t2 reported
  a viewport a hundred pixels wide and every coordinate measured against it was
  wrong. AnoaBrowser resizes every view on resizeEvent and at creation.

- A hidden QWebEngineView processes no input at all — not Qt synthetic events,
  and not CDP Input.dispatchMouseEvent either. Both paths still answer
  "clicked". Reads work fine on a hidden view, which is what makes this easy to
  miss. See bugs.md for the multi-tab feature.

- Do not host tabs in a QStackedLayout. It hides every view but the current one,
  and a hidden QWebEngineView processes no input at all — not Qt synthetic
  events, not CDP Input.dispatchMouseEvent — while both paths still answer
  "clicked". Reads keep working, so the gap is invisible until something clicks
  a background tab and nothing happens. Views are children at the container's
  geometry with the active one raised, each show()n at creation: a view that was
  never shown takes no input even once it is raised.

- NSS is a host-first library, for the same reason GL and libX11 are. libnss3.so
  is a link-time dependency so a dependency walk bundles it, but NSS loads
  libsoftokn3, libfreebl3 and libnssckbi at RUNTIME — ldd never names them, so
  nothing packages them, and the bundled libnss3 then shadows the host's
  coherent set and hunts for modules that are not there. Chromium reads
  certificates through NSS, so the symptom is every HTTPS page failing while
  local commands keep working.

- The host-first shim's glob was lib/hostfirst/*.so.* — a dot after .so.
  libGL.so.1 matched, libnss3.so did not. Any library without a version suffix
  silently never reached the shim. Both spellings are matched now.

- AppImage: the runtime appimagetool embeds dlopen()s libfuse.so.2, which Ubuntu
  dropped in 22.04, so it fails on a current Ubuntu before the payload runs.
  Build with --runtime-file from AppImage/type2-runtime, which links FUSE
  statically. On a host with no FUSE at all, APPIMAGE_EXTRACT_AND_RUN=1 works but
  unpacks the payload every invocation: ~6s per command against ~1s for the
  tarball, so it is a fallback and not a mode to live in.

- "Minimal Linux" for a browser means Chromium's runtime set, not one or two
  packages. Chasing it one error at a time gives a misleading answer: the first
  failure names ca-certificates, the next names libnss3, and neither is the
  whole list. The Dockerfile's 24 packages are the real answer, and they apply
  equally to the tarball and the AppImage.

- `--tab` only worked AFTER the verb, and the README, help and core skill all
  documented it BEFORE one. The pre-scan hands everything before the verb to the
  browser parser, which has never heard of --tab, so the documented idiom died
  with "Unknown option 'tab'". The five addressing options — --tab, --port,
  --host, --token, --auth-token — are moved across the verb boundary now,
  because they name a browser rather than describe one and mean the same thing
  on either side. Everything else still belongs to whichever side it was typed.

- takeOption did not understand --opt=value at all. QCommandLineParser accepts
  that spelling for every browser option, so --tab=t2 looked reasonable and was
  silently dropped: the command ran against the wrong tab and said nothing. It
  handles both spellings now.

- Reported by a user driving the CLI for real, not by any test. The suites all
  used the after-the-verb form, which is exactly the half that worked.

- Tab names are an ALIAS for the minted id, never a replacement. Both resolve to
  the same tab, and isValidTabName rejects anything shaped like an id
  (^t[1-9][0-9]*$) — without that rule, a tab named "t2" would make --tab t2
  mean either tab depending on lookup order.

- Resolution happens in four places and every one of them had to learn names:
  the CDP client's target picker, /render/*'s ?tab=, `anoa tab select|close`, and
  Target.* over the proxy. The subtle one is /render/*: the resolved view is
  enough for a screenshot, but the input helpers look a tab up by ID, so the
  query value has to be normalised to the id or a named tab takes screenshots
  and ignores clicks.

- "no browser on host:port — start one first" was printed for a browser that IS
  running but has no such tab. Wrong advice, and it predates tab names: any
  --tab t99 produced it. The client now flags a tab miss separately.

- Sessions were lost on SIGTERM/SIGINT. Chromium writes cookies and local
  storage lazily and flushes when the profile is destroyed; browser mode had NO
  signal handling, so a signal killed the process before any of it reached disk.
  `--profile work` created its directory and wrote Favicons and Session Storage
  but never a Cookies file — a profile that looked like it was working. `anoa
  close` was always clean, which is why nothing caught it: the documented exit
  flushed and every other one did not.

- QWebEngineProfile::defaultProfile() is OFF-THE-RECORD. With no --profile,
  anoa kept nothing at all — log in, exit, logged out, silently. The default is
  a persistent profile named "default" under QStandardPaths::AppDataLocation
  now; --ephemeral asks for the old behaviour.

- PRF-03 asserted that no --profile writes NO directory. That was a test
  describing the bug as intended behaviour. It asserts the default profile
  exists now, with a sibling case for --ephemeral.

- QWebEnginePage's dialog defaults BLOCK the renderer waiting for a click that
  never comes. One alert() killed the whole browser: every later command timed
  out, including Target.getTargets at the browser level, and only SIGKILL got it
  back. Any ordinary site with a confirm did it. AnoaPage answers and records
  them now.

- Qt drops what nobody accepts, silently, in three more places: downloads
  without a downloadRequested handler, window.open without createWindow, and
  file inputs without chooseFiles. None of them error — the page simply does
  not work, which is far harder to diagnose than a failure.

- DOM.requestNode answers out of a node map that does not exist until DOM.enable
  and one DOM.getDocument have run. Without them it fails with an EMPTY error
  message, which reads as "wrong element" rather than "domain asleep".

## feat/embeddable-live-view (2026-08-16)

- /render was a 500 ms PNG poller with no input and no tabs. It is now an MJPEG
  live view with a tab bar, a URL bar and full mouse/keyboard forwarding, served
  from a Qt resource rather than a C++ format string.
- Found while wiring it: /render/stream.mjpeg called browser->grab(), which
  grabs the container and therefore whatever tab is raised. ?tab= was resolved,
  404'd correctly for a bad id, and then ignored. Streaming a background tab
  gave you the active one with nothing anywhere to say so.
- Input primitives that did not exist: mouse move, separate press/release, and
  modifiers on anything. Without them there is no hover, no drag, no text
  selection and no Ctrl+A — the click endpoint can drive a page from a script
  but cannot be driven by a pointer.
- HiDPI: grab() is device pixels, the input endpoints are logical pixels. Added
  GET /render/viewport so a client never has to guess from the image.
- Embedding is opt-in by origin (frame-ancestors 'self' by default,
  --embed-origin to widen). The view forwards keystrokes, so framing it is
  handing over the session, not showing a picture of one. Verified both ways by
  screenshotting a cross-origin host page: blocked renders Chromium's broken-
  document icon, allowed renders the viewer.
- The old page substituted the server's auth token into the HTML, so every
  authenticated GET /render returned a document with the secret in it. The new
  page is static and reads the token from its own query string instead.
- Menulis contoh embed (examples/embed/) langsung membongkar celah yang tak
  terlihat dari uji endpoint: --embed-origin mengizinkan sebuah origin
  menyematkan DAN mengemudikan browser, tapi fetch ke /json/list tetap ditolak
  karena tak ada header CORS. Jadi aplikasi tuan rumah bisa menampilkan view dan
  tidak bisa menggambar bilah tab di sekelilingnya — yang justru sebagian besar
  alasan orang menyematkannya. CORS kini memakai daftar origin yang sama.
  Pelajarannya: menulis contoh yang benar-benar dijalankan menemukan hal yang
  tidak ditemukan suite endpoint, karena suite memanggil server tanpa origin.
- /render/scroll tidak pernah bekerja di macOS, dan tak ada satu tes pun yang
  memeriksa halaman benar-benar bergerak — endpoint menjawab "scrolled" dan
  halaman diam. macOS tak punya wheel tanpa fase: Qt mengirimnya sebagai gestur,
  dan QtWebEngine memetakan Qt::NoScrollPhase ke fase Blink yang dibuang
  Chromium, jadi peristiwanya diposting, diterima, lalu hilang sebelum sampai ke
  halaman. Linux/aarch64 benar sejak dulu — dibuktikan dengan menjalankan rilis
  v0.10.1 di papan RK3588, yang scroll-nya jalan. Pelajaran: menjalankan suite
  hanya di satu OS tidak akan pernah menemukan ini.
- Inspect element ternyata sudah tersedia penuh dan tak punya jalan masuk:
  frontend DevTools Chromium disajikan di port+1 dan berbicara ke halaman lewat
  proxy CDP di port+2, persis yang sudah disebut webSocketDebuggerUrl. Yang
  ditambahkan hanya tombol.
- Dua kelemahan harness tes yang membuat angka menyesatkan: vitest melaporkan
  beforeAll yang melempar sebagai "skipped", bukan "failed", sehingga satu berkas
  penuh (10 kasus pdf_handler) hilang di balik "0 gagal"; dan /json/list sah-sah
  saja kosong sesaat setelah start karena id target Chromium belum diresolusi,
  sementara startBrowser hanya menunggu port terikat.
